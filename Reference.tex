\subsection{Segment Tree}
A segment tree is stored as a vector of the datatype it stores. For simple problems, an int type is enough. For more complex or lazy propagation, a Node structure is required. The segtree is stored in a list, that must have a size of $4n$, where $n$ is the size of the given array $a$. This is necesary so the binary tree that holds the segtree is complete and can behave correctly.

\paragraph{Elements of a SegTree} To build a segment tree, these things are required: an operation, that must be \textbf{associative}, have an \textbf{identity elemeny} and, preferably, it must be \textbf{conmutative}.

\paragraph{Structure} Each node of a segtree has a node, and given a node $i$, it's left child is at index $2i$, and it's right children is at $2i + 1$. The root is at $i=1$.

\paragraph{Operations} The operations on a SegTree usually include the following:
\begin{itemize}
 \item The index of the node, usually $i$
 \item The range over the list, $[l, r]$, where $l \geq 0;~ r <n$.
\end{itemize}
It's important that the range over the list is used as \textbf{zero indexed}, because the original array is zero indexed too.

\subsubsection{Recursive}
\paragraph{Intuition} Each recursive function call represent a current node. This is achieved by passing an $i$ parameter, which is the index of the node inside of the vector representing the tree. Also, two other parameters (tl and tr, standing for temporal low and temporal high respectively) represent the ``reach'', or the interval over the original list of elements a that the current node represents (as $[tl, th]$).

\paragraph{Elements} The following are the elements required for a recursive segment tree. Each element is defined as following:

\begin{itemize}
 \item vector$<$int$>$ tree: The tree itself
 \item vector$<$int$>$ a: The original list of elements, read directly from stdin.
 \item int n: The size of a, the number of elements on the list input.
 \item int N: The length of the vector that holds the tree, $N=4n$
\end{itemize}

\lstinputlisting[caption=Recursive segtree declaration stuff - common.cpp]{./ref_algos/recursive_segtree/common.cpp}

Building is done starting from the root, where $i=1$. The recursive function descends through every branch, reducing the segment that each node covers (where the interval covered by node $i$ is defined as $[tl, tr]$) in half each time, similar to a binary search.

\subsubsection{Iterative}
The iterative version walks the tree starting from the leaves, and walks up until it reaches the root. The representation on the vector is the same.

\paragraph{Building} It's not necesary to have a special build function. Utilizing the update function can acomplish the same goal.

\paragraph{Update} Now, the representation in memory is as follows: The original array's elements are on the second half of the vector. So if we have $n$ elements in array $a$, then the first element $a_1$ will be on position $tree[2n]$, because we keep the array 0-indexed. Then the rest of the tree is found on the positions $i \in [1, 2n-1]$. So, to update, $pos$ must be the 0-indexed position of the element that will be updated. (TODO: is this true?)

\subsubsection{Lazy Propagation}

Lazy progapation solves the problem for update queries on an interval, they can be set queries, sum queries, or anything involving modifying an interval. The idea is queue the modification on a parent node, until it becomes necesary to update any further. It's more easily implemnted in a recursive way.

\paragraph{Example} This example segment tree is prepared for the following queries:
\begin{itemize}
 \item Range sum query with $a, b, k$
 \item Range set query with $a, b, k$
 \item Range sum query with $a, b$
\end{itemize}
